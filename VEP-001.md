# VEP-001: Velyx Wire Format and Capability Negotiation (V1)

- Status: Draft
- Type: Standards Track
- Created: 2026-06-11
- Author: mjojo (https://github.com/GLK-Dev)
- Requires: None

## 1. Abstract
This proposal specifies the canonical Velyx V1 wire format, packet taxonomy, replay-protection requirements, and capability/version negotiation carried inside the Noise XX handshake payloads.

The goal is deterministic interoperability across independent implementations.

## 2. Scope
This VEP defines:

1. Packet header and binary encoding.
2. Packet type registry for V1.
3. Sequence and replay window rules.
4. Handshake payload formats: ClientHello, ServerHello, ClientFinish.
5. Version and capability selection algorithm.

This VEP does not define DHT behavior, relay economics, or FEC coding internals.

## 3. Terminology
- Endpoint: one side of a Velyx session.
- Direction: sender-local stream of packets (each side maintains its own sequence numbers).
- Session: post-handshake secure channel identified by session_id.
- Capability mask: 64-bit feature bitmap.

Normative terms MUST, SHOULD, MAY follow RFC 2119 semantics.

## 4. Transport and Crypto Baseline
1. Underlay transport: UDP.
2. Handshake cipher suite: Noise_XX_25519_ChaChaPoly_BLAKE2s.
3. After handshake completion, all application payloads are encrypted in Noise transport mode.

## 5. Wire Header (V1)
All integer fields use network byte order (big-endian).

Header length is fixed: 28 bytes.

1. magic (4 bytes): ASCII VLYX (0x56 0x4c 0x59 0x58).
2. version (1 byte): protocol version, V1 = 0x01.
3. packet_type (1 byte): message kind.
4. flags (2 bytes): reserved, MUST be 0 in V1 unless a future VEP defines bits.
5. session_id (8 bytes): session identifier.
6. seq (8 bytes): per-direction packet sequence.
7. payload_len (4 bytes): payload size in bytes.
8. payload (N bytes): packet payload.

Validation requirements:

1. Receiver MUST reject packets with invalid magic.
2. Receiver MUST reject unsupported version.
3. Receiver MUST reject if actual payload size does not equal payload_len.
4. Receiver MUST validate expected packet_type at each state transition.

## 6. Packet Type Registry (V1)
1. 0x01: Handshake1
2. 0x02: Handshake2
3. 0x03: Handshake3
4. 0x10: Data
5. 0x11: Ack
6. 0x12: Control
7. 0x13: Keepalive
8. 0xff: ErrorPacket

## 7. Sequence, Nonce, Replay Rules
1. Each endpoint MUST start outbound seq at 0 for a new session.
2. Each outbound packet MUST increment seq by exactly 1.
3. seq is per-direction and independent between endpoints.
4. Receivers MUST enforce duplicate detection and stale-window rejection.

Replay window:

1. Minimum window size: 128 sequence numbers.
2. Duplicate seq within window MUST be rejected.
3. Packets older than the window lower bound MUST be rejected.

Nonce guidance:

1. In V1, Noise transport internals handle AEAD nonce state.
2. seq is still mandatory for replay and future explicit nonce derivation profiles.

## 8. Capability Negotiation
Negotiation is embedded in the encrypted payloads of the Noise XX handshake messages.

### 8.1 ClientHello (10 bytes)
1. min_version (1 byte)
2. max_version (1 byte)
3. caps (8 bytes, u64 bitmask)

### 8.2 ServerHello (19 bytes)
1. min_version (1 byte)
2. max_version (1 byte)
3. caps (8 bytes)
4. selected_version (1 byte)
5. selected_caps (8 bytes)

### 8.3 ClientFinish (9 bytes)
1. selected_version (1 byte)
2. selected_caps (8 bytes)

## 9. Selection Algorithm
Given local endpoint L and remote endpoint R:

1. Shared version range is [max(L.min_version, R.min_version), min(L.max_version, R.max_version)].
2. If shared range is empty, handshake MUST fail.
3. selected_version MUST be the highest version in shared range.
4. selected_caps MUST be bitwise intersection (L.caps AND R.caps).
5. ClientFinish MUST echo selected_version and selected_caps from ServerHello.
6. Any mismatch in echoed values MUST terminate handshake.

## 10. Session and State Requirements
1. Initiator MUST choose session_id randomly (u64) for each new handshake.
2. Responder MUST enforce constant session_id continuity for all packets in the session.
3. Endpoints SHOULD reject packets from unexpected source address during active handshake.

## 12. Security Considerations
1. Replay resistance depends on strict seq and sliding-window enforcement.
2. Downgrade resistance depends on strict validation of selected_version and selected_caps.
3. Implementations SHOULD rate-limit malformed packets and handshake attempts.
4. session_id randomness MUST use a cryptographically secure RNG.

## 13. Backward Compatibility
V1 endpoints only support version 1. Future versions MUST keep explicit version signaling and either:

1. negotiate a lower mutually supported version, or
2. fail closed.

## 14. IANA-like Notes
No external registry is used. Packet type and capability assignments are governed by VEP process.
